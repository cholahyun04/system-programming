<과제 1번에 대한 질문과 AI의 답변>

질문1: 단일 파이프로는 왜 양방향 통신이 불가능하며, 두 개를 생성해야 하는가?
파이프는 단방향이라서. 하나의 파이프로 양방향 통신 시 자신이 쓴 데이터를 자신이 다시 읽는 데이터 충돌이 발생하기 때문이다.

질문2: 사용하지 않는 파일 디스크립터(fd)를 명시적으로 close() 해야 하는 이유는 무엇인가?
쓰기용 fd가 하나라도 열려 있으면 상대방의 read()가 데이터 수신을 무한정 대기하여 데드락에 빠질 수 있기 때문이다.


<과제 2번에 대한 질문과 AI의 답변>

질문1: execlp 대신 execvp를 사용한 이유는?
execlp는 코드 작성 시점에 인자 개수가 고정되어 있을 때 사용하며, 인자 개수를 알 수 없는 커맨드라인 입력은 배열 형태로 넘기는 execvp가 적합하기 때문이다.

질문2: 구분자 위치에 argv[split_idx] = NULL;을 굳이 넣은 이유는?
execvp 등 exec 계열 함수는 인자 배열의 끝을 무조건 NULL 포인터로 판별하므로, 첫 번째 명령 인자의 끝을 명시적으로 시스템에 알려주기 위함이다.

질문3: 부모 코드에서 close(fd[0]); close(fd[1]);을 빼먹으면 어떤 문제가 발생하나?
부모의 쓰기용 디스크립터가 열려 있으면 두 번째 프로세스(뒤 명령)가 파이프에서 더 읽을 데이터가 남은 줄 알고 무한 대기하여 프로그램이 종료되지 않기 때문이다.


<과제 3번에 대한 질문과 AI의 답변>

질문1: 왜 파이프(pipe()) 대신 FIFO(mkfifo())를 사용해야 하는가?
파이프는 부모-자식 등 파생 관계가 있는 프로세스 간에만 쓸 수 있지만, FIFO는 파일 시스템의 이름을 공유하므로 전혀 관계없는 독립된 프로세스끼리도 통신할 수 있기 때문이다.

질문2: 3_fifo_read를 먼저 실행했을 때 프로그램이 바로 끝나지 않고 멈춰 있는 이유는 무엇인가?
open() 함수는 기본적으로 상대방이 반대쪽 모드(쓰기)로 FIFO를 열 때까지 진행을 멈추고 블로킹(대기) 상태에 머물도록 설계되어 동기화를 맞추기 때문이다.

질문3: 통신이 끝난 후 반드시 unlink()로 FIFO 파일을 지워야 하는 이유는 무엇인가?
FIFO는 디스크에 실제 특수 파일 형태로 생성되므로, 사용 후 명시적으로 삭제하지 않으면 찌꺼기로 계속 남아 추후 동일한 이름 생성 시 충돌을 일으킬 수 있기 때문이다.
